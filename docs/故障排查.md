# 故障排查

← 回到 [README](../README.md)

## 先跑这两个

```
python tools\csgotool.py mods      # mod DLL 到底进没进进程
python tools\csgotool.py doctor    # 管道 / 插件版本 / 错误日志
```

`doctor` 一次报出：管道是否响应、`lan_pipe` / `lan_fix` 实际加载的版本、botmimic 与 kgns 两个插件
的探针 cvar、`lan_fix` 最后一行日志、当天错误日志的大小和时间、在线真人数量。
**它会先打 mods 那一行再查管道**——"插件没应答"和"引擎从来没加载 addons"从外面看一模一样，
而只有后者是 `-insecure` 能治的。

## 症状表

| 症状 | 原因 | 处理 |
|---|---|---|
| 对局正常，但没有皮肤、没有 bot 强化、工具连不上 | **缺 `-insecure`**：VAC 安全会话里引擎完全不加载 addons 里的 DLL（磁盘上文件全在、大小正确） | `mods` 确认；Steam 启动选项加 `-insecure`。见 [开局与自动启动](开局与自动启动.md) |
| `Unknown command "sm"`，但 `meta list` 有回答 | Metamod 挂载点在建图时，客户端主菜单那张图已经先加载过 gamedll | 换一次图 `changelevel <图>`。**每次启动只需一次，不是每局** |
| `管道没有响应` | 游戏在 ESC 暂停菜单 / 主菜单 / 读图中；或插件没加载 | 看 27015 是 TCP 还是 UDP 占用：只有 TCP = 还在主菜单；关掉暂停菜单；`doctor` 复查 |
| `sm_ws` / `sm_knife` 在控制台敲了没反应也不报错 | kgns 的回调第一行是 `if (IsValidClient(client))`，控制台里 `client = 0` 被拒，但插件仍返回 `Plugin_Handled` | 让玩家触发：聊天 `!ws` / `!gloves` / `!knife`，或 `bind f3 "sm_knife"`（绑定命令带玩家索引）。`sm version` / `sm plugins list` 这类**核心命令在控制台是能答的**，所以"核心能答、我的插件静默"= client 索引问题，不是装坏了 |
| `sm plugins reload plugins/xxx.smx` 跑了但版本没变 | reload **只认裸文件名**，带 `plugins/` 前缀会被接受且静默什么都不做 | `exec sm plugins reload lan_fix.smx`，再看 `doctor` 里的版本标记 |
| 版本 cvar 和日志不一致 | SourceMod 在帧末才释放被 reload 插件的 cvar，旧 `sm_*_version` 会滞留 | 以插件写进自己日志的 `"<name> <version> loaded"` 为准，`doctor` 读的就是这个 |
| 刀那行是灰的 / 点不动 | kgns 刻意锁的：没选过刀模型时 `g_iKnife[client] == 0` | 先在单独的刀模型菜单里选一把刀，`!ws` 里那行才解锁 |
| 改完皮肤没变化 | 该玩家当前没带这把枪 | 插件会回 `carries no xxx: persisted, buy it and re-run`，买出来再执行一次 |
| 皮肤设了但渲染成默认模型 | 把 paintkit 号塞给了它没被授权给的武器 | 工具的类别守卫会拦；绕过守卫（`--force`）就要自己负责 |
| 朋友列表里找不到房间 | 这个 build 不应答 A2S | 只能 `connect`，见 [局域网联机](局域网联机.md) |
| bot 数值和 `botprofile.db` 对不上 | `bot_stuff.smx` 每 tick 覆盖四个字段 | 这是设计如此，看 `bots` 的"接管"列；要拉平见 [bot 强度与皮肤](bot强度与皮肤.md) |
| 每局 bot 强度不一样（有人 0.40 秒反应） | 名字随机抽，弱档 block 也在池子里 | `bots patch --names` |
| 中文输出乱码 | 控制台代码页 cp936 | 工具内部已强制 UTF-8 输出；仍乱码就 `chcp 65001`，或直接看 `tools` 下重定向的文件 |
| `Error parsing BotProfile.db - unknown attribute 'Rank'` | **不是我们的文件造成的**：Valve 出厂那份里就有同样 8 行 `Rank =`，是这个 build 的解析器不认 | 忽略 |
| 日志里 `AddMultiDamage: g_MultiDamage.GetDamageForce() == vec3_origin` | CS:GO 引擎自身的伤害事件告警 | 与插件无关，忽略 |

## 判据的先后顺序

出问题时按这个顺序排除，能省掉大部分来回：

1. `mods` —— 引擎有没有把 addons 装进进程。（缺 `-insecure` 在这里露馅，且只有在这里）
2. `install --audit` —— 文件层缺了什么、依赖链断在哪、db 覆盖够不够（不用开游戏）。
3. `install --check` —— 现场字节与上游清单是否一致（有没有被人改过、改过的是不是意料之中的）。
4. `doctor` —— 管道有没有应答、插件版本标记对不对、错误日志有没有在长。
5. `dialog` —— 只有屏幕上能看到的那些弹窗原文。

**端口占用不能证明任何东西**：CS:GO 客户端自己就会绑 UDP 27015，停在主菜单时也一样；
这台机器上 `127.0.0.1:27015` 还可能被无关的本地代理（Watt Toolkit / Steam++）占着。
唯一的活性信号是文件管道被插件吃掉。

## 错误日志的命名

SourceMod 的错误日志按天命名：`logs/errors_YYYYMMDD.log`（不是 `Error.log`）。
工具按 mtime 取最新的那个，所以跨零点不会突然什么都不报。
`sm plugins refresh` 能装新文件，但**加载的证据只有产物**——每个自写插件在 `OnPluginStart`
会写一行启动标记，`doctor` 读的就是它。
