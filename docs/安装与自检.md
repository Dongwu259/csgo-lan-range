# 安装与自检

← 回到 [README](../README.md)

装的是第三方插件栈（Metamod / SourceMod / PTaH / kgns weapons+gloves / sm-ripext / bot 强化那批），
加上我们自己的两个插件。全部由 `configs\components.json` 这一个清单驱动：版本、URL、字节数、
SHA-256、许可、保留名单、挂钩位置都在里面。

## 从零装插件

```
python tools\csgotool.py install --dry-run    # 只看计划，一个字节都不写
python tools\csgotool.py install              # 真装，落地前会再问一次
```

`install` 的次序是刻意的：下载六个 release 包 → **先比字节数再比 SHA-256** → 解压到 `staging\`
并逐文件按 CRC 复核 → 算出计划（新增 / 替换 / 已相同 / 你改过所以保留）→ 要替换的文件先复制进
`backup\install\<时间戳>\` → 落地 → 给两个 Valve cfg 追加 `exec` 行、把 `core.cfg` 的
`FollowCSGOServerGuidelines` 改成 `no` → 解除 MOTW → 写 `report.json`。
**校验有任何一项不过就停下来，现场不动。**

## 三种"只看不动"的模式

| 命令 | 回答的问题 | 需要什么 | 退出码 |
|---|---|---|---|
| `install --dry-run` | 这次会写哪些文件 | 下载缓存（没有就联网） | 0 |
| `install --check` | 现场字节与清单一致吗 | 下载缓存 | 0 = 一致，1 = 有漂移 |
| `install --audit` | 这套栈自不自洽（另一类问题） | 都不需要，游戏也不用开 | 0 = 没坏，1 = 有缺件 |

`--audit` 查的是 `--check` 看不见的那一半：

- 清单声明的 `.smx` 有没有缺（装到一半崩过的现场）
- 依赖链断没断：`bot_stuff → bot_steamids → SteamIDConverter.ext → bot_info.json`、
  `botmimic → eitems → rip.ext + gamedata/botmimic.games.txt`（这些链是从 `sm plugins list`
  的报错行学来的，不是文档里抄的；链断了插件会加载干净然后什么都不做）
- `FollowCSGOServerGuidelines` 现在是什么、两个 cfg 的 `exec` 挂钩在不在
- `botprofile.db` 的档位分布与名字命中率（就是"强度抽卡"有没有还在）
- 哪些本地 `de_` 图没有道具路线数据、`spcomp.exe` 在不在、`data` 目录可写
- addons 下还有几个 DLL 带着 Web 标记（引擎会拒绝加载这些）

坏了退 1；只是"可以更好"就打成 `[建议]` 且不影响退出码——CI 里可以直接用。

## 保留名单与同意门

- 你在插件配置里做的改动（`core.cfg`、`cfg\sourcemod\` 下那些、自己重编译过的 `botmimic.smx`）
  在清单的 `preserve` 名单里：**只跳过，不覆盖**，`--check` 会单独列出"这个你改过"。
- bot 强化那批（`botpack`）的上游仓库**没有 LICENSE 文件**，所以要么 `--accept-upstream-license`
  要么交互确认，抓取动作由你的机器对上游做。理由与细节见
  [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。不想碰它就 `install --skip botpack`。
- `botpack` 会把你游戏根目录的 `botprofile.db` 换成上游那份。**这一步是整套 bot 栈的开关**：
  `bot_stuff.smx` 是按 bot 名字去 `data/bot_info.json` 查表才决定接不接管，而 Valve 默认名字
  （`Ron`、`Yahn`…）一个都不在表里——不换文件的话插件加载得干干净净，然后什么都不做。
  原文件先复制进还原点，`uninstall` 会拿它盖回来。强度本身还能再拉平，见
  [bot 强度与皮肤](bot强度与皮肤.md)。
- 清单里明确**不装**的文件（现在只有上游的 `botchatter.db`）每次都会打印出来并附原因，
  不会静默少装。
- 游戏进程在跑就拒绝执行——文件被占着会留下半个插件栈；确认自担风险才用 `--force`。

## 装完要做的（首跑清单）

`install` 结束时自己会把这张表打出来，内容与 `configs\components.json` 里的 `first_run` 一致：

1. Steam 里给 csgo legacy 的启动选项写 `-insecure`。**这一步脚本代不了**：没有它引擎不加载
   addons 里任何未签名 DLL，而对局看起来完全正常（见 [故障排查](故障排查.md)）。
2. 开游戏，主菜单点 开始游戏 → 与电脑玩家，选一张 `de_` 图。脚本能免掉这一跳
   （`start --launch`），但那样起来的局不是竞技玩法——详见
   [开局与自动启动](开局与自动启动.md)。
3. 进图后换一次图（`changelevel de_mirage`）。Metamod 只在换图时装载，不换图时
   `sm version` 会答 `Unknown command`。
4. `python tools\csgotool.py mods` —— 8 个 mod DLL 都该列出来。
5. `python tools\csgotool.py doctor` —— 管道应答应有，插件版本应列出。
6. 想让每局 bot 同一档强度：`python tools\csgotool.py bots patch --names`。
7. 皮肤在游戏里用 `!ws` / `!gloves` / `!knife` 选（控制台直接敲 `sm_ws` 会以 `client=0` 运行，
   菜单不出现）。

## 还原

```
python tools\csgotool.py uninstall --revert <时间戳>    # 不给时间戳就是最近一次
```

它只按那一次 `report.json` 记录行动：删掉它新增的、恢复被换掉的（包括 `botprofile.db`）、
撤掉那两行 `exec` 和 `core.cfg` 的那一格。别的文件它不碰，所以你自己改过的东西不会丢。

## 打包版的行为差异

清单和两个自写 `.smx` 用 `--add-data` 进了 exe，运行时从 `sys._MEIPASS` 里读；
区别只有一个——**还原点落在 exe 旁边的** `backup\install\<时间戳>\`，因为写操作一律锚在
`sys.executable` 所在目录（onefile 下 `__file__` 指向临时解压目录，写在那里会随进程退出消失）。
