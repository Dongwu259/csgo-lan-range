# 规则、配置与校验

## 单挑预设

```
python tools\csgotool.py duel --rounds 10 --money 4750 --weapon awp --freeze 5 --bots 0 --apply
```

| 参数 | 作用 |
|---|---|
| `--rounds N` | `mp_maxrounds N`，并顺手关掉 `mp_overtime_enable`、`mp_halftime`、`mp_teams_unbalance_limit`（单挑不该被中场/加时/人数不平衡打断） |
| `--money N` | 每回合出生把钱包写成 N。**为什么不是 cvar**：经济里没有任何变量能"把指定玩家补到指定金额"，`mp_startmoney` 只在经济重置时触发 |
| `--weapon a,b` | 每回合出生发这些枪，逗号分隔；名字会拿皮肤表的 53 个武器 key 校验，写错当场拒绝 |
| `--no-strip` | 只加枪，不清空原有武器（默认会清空主武器/手枪/道具/C4，**但保留刀**，这样发枪失败也不会让人空手） |
| `--freeze N` | `mp_freezetime N` |
| `--bots N` | `bot_quota N`；真 1v1 用 0（实测：这个 build 没有 `sv_hibernate_when_empty`，清空 bot 后管道照样响应） |
| `--target` | `humans`（默认，双方都套）/ `all` / `bots` / 某个玩家名 |
| `--apply` | 对当前活着的人立刻套一次，不用等下一回合 |
| `--show` / `--off` | 看现在套了什么 / 关掉自动发枪+清枪+补钱 |

两个坑：

- `--target humans` 在你自己处于观战位时**不生效**（出生钩子故意跳过 `GetClientTeam < 2`）。
  `who` 里 `team=1` 就是观战位。先确认队伍列再怀疑钩子。
- 回合数、冻结时间这类是 cvar，`duel --off` 不会替你改回去；`--show` 会列出当前值，用 `set` 还原。
  **`--rounds` 会当场生效并可能直接结束正在打的局**（实测设 3 时 CT 已 4 胜，那局立刻终止重开）。

发枪、清枪、补钱这三件事在插件里，不在 cvar 里：`lan_fix.smx` 的
`sm_lanfix_auto` / `sm_lanfix_strip` / `sm_lanfix_money` / `sm_lanfix_autoapply` / `sm_lanfix_autoshow`，
`duel` 只是把这套包起来。`autoshow` 里的 `m_iAccount` 是真实 `GetEntProp` 读数，所以它可以当判据。

## 读写参数与执行命令

```
python tools\csgotool.py get  mp_maxrounds
python tools\csgotool.py set  mp_maxrounds 24
python tools\csgotool.py exec mp_warmup_end
python tools\csgotool.py map  de_inferno
python tools\csgotool.py cfg  gen practice --set mp_freezetime=5 --set mp_maxrounds=99
python tools\csgotool.py exec "sm plugins reload lan_fix.smx"
```

- `set` 会**读回验证**，不一致会明确告诉你 `DIFFERS`。
- `exec` 是逃生舱：任何服务器控制台命令和插件命令都能走，包括 `sm_lanfix_*`。
- `map` / `start` 换图前先对 `maplist.txt`、`mapcycle.txt`、`csgo\maps\*.bsp` 和道具数据库核对；
  只在 vpk 里的图会警告但仍会尝试（切完用 `status` 确认）。
- 记一条时序：`changelevel` 会重跑 `listenserver.cfg` 和 `gamemode_competitive_offline.cfg`，
  所以 `bots_improved.cfg` 会被重新应用；你的自定义 cfg 要靠 `exec` 排在它后面才生效。
- 回合切换会重新断言一些值（实测 `sv_cheats` 被 `bots_improved.cfg` 抬回 1、`mp_warmuptime` 读回 300、
  `sv_maxupdaterate` 读回 64 而不是 60），所以**在下一回合开始之后再读 cvar**，不要信刚 exec 完的快照。

## 参数名从哪来的可信度

```
python tools\csgotool.py verify lan.cfg
```

`verify` 拿 cfg 文件里每个标识对 `server.dll` + `engine.dll` 做**整词字节搜索**——这是这套工具里
所有参数名的来源保证，不依赖网上抄的 cvar 列表。自己写 cfg 时先 `cfg gen`，再 `verify`，
不存在的变量名会被点名。

几个字面意思与直觉相反的（都是从 `server.dll` 的 help 字符串里读出来的，不是猜的）：

| cvar | 真实语义 |
|---|---|
| `mp_startmoney` | "amount of money each player gets **when they reset**" —— 设 16000 会**每回合重置**经济，真人也一起被补满 |
| `bot_eco_limit` | "bots **will not buy if their money falls below** this amount" —— 设 20000 而 `mp_maxmoney` 16000 是永远达不到的阈值，bot 于是永远不 eco 买 |
| `sv_bots_force_rebuy_every_round` | 每回合剥光 bot 的武器强迫重买，**不碰真人金钱** |
| `sv_bots_get_easier_each_win` | bot 连胜时被悄悄降低难度 |
| `mp_afterroundmoney` | 回合奖励（Valve 默认 0） |
| `sv_pure` | **这个 build（13881）里不存在**，`lan.cfg` 里那行标了 no-op |

Valve 在这份 build 上的竞技基线（`cfg/gamemode_competitive.cfg`）是 `mp_freezetime 15`、
`mp_roundtime`/`_defuse`/`_hostage` 全 **1.92**、`mp_maxrounds 30`、`mp_startmoney 800`、
`mp_maxmoney 16000`、`mp_buytime 20`。调回合节奏前先读它——我发明过三次错误值
（没有冻结时间、5 分钟回合对 MR15、只改 `mp_roundtime` 导致解救人质图和炸弹图时长不一致）。

## 玩法规则本身

- **已创建的对局改不掉玩法**（`game_type`/`game_mode` 写完 `changelevel` 也不换规则），
  判据是 `csgotool.py mode`。细节见 [开局与自动启动](开局与自动启动.md)。
- **不要把 `sv_lan` 设成 1**：后果见 [局域网联机](局域网联机.md)。
