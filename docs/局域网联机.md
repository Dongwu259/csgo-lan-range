# 局域网叫朋友打一局

← 回到 [README](../README.md)

**这套东西只用于本地和局域网自娱。** 皮肤靠伪造 netprop、bot 靠改内存偏移，在官方匹配或别人的
服务器上都是找封。UDP 27015 不要往公网做端口映射——文件管道等价于本机的任意命令执行通道；
防火墙放行命令工具只会打印出来给你看，不替你执行（它也没有管理员权限）。

## 步骤

1. 开局。两种方式，见 [开局与自动启动](开局与自动启动.md)：竞技局要回主菜单点一次
   开始游戏 → 与电脑玩家；`start de_nuke --launch` 能免点菜单但玩法不是竞技局。
2. 应用联机配置并进图：

   ```
   python tools\csgotool.py start de_ancient --now
   ```

   `start` 会：检测服务器是否已在跑 → `exec lan.cfg` → `changelevel` 到目标图 → 等图真正加载完
   → `--now` 时执行 `mp_warmup_end` 让正赛立刻开始 → 打印加入地址。
3. 生成给朋友的东西：

   ```
   python tools\csgotool.py join --write-cmd
   ```

   输出告诉你三件事：本机各网卡地址、**同网段范围**、以及 `lan\join-<IP>.cmd`。那个 `.cmd` 发给
   朋友，双击即连（有密码时密码就写在链接里，**所以这个文件别发到公网群里**）。

## 三种写法

| 写法 | 形态 | 说明 |
| --- | --- | --- |
| 控制台 | `connect <房主局域网 IP>:27015 <密码>` | 一定有效，但要朋友自己敲 |
| 一键 | `steam://connect/<房主局域网 IP>:27015/<密码>` | Valve 文档里第三段就是密码。2026-10-31 实测：链接确实送到了游戏，但被 Steam 拒了，弹「服务器指定的 app id 无效」——Steam 要靠服务器查询判断这台服务器属于哪个 app，而这个 build 不应答 A2S |
| 启动项 | `+connect <房主局域网 IP>:27015 <密码>` | 填进朋友自己的 Steam 启动选项，之后每次开游戏自动进房。`client.dll` 里有 `Executing deferred connect command`，说明 `+connect` 会被主菜单延后执行而不是丢掉——这正是第三方平台"一键进房"用的机制 |

朋友那边还有个硬前提：他装的必须也是 **Counter-Strike: Global Offensive (Legacy)**
（appid 4465480，同一个 build）。装 CS2 连不进来，协议对不上。

**他不需要 `-insecure`，也不需要装任何插件、任何 Python。** `-insecure` 只解决一件事：
让**服务器所在那个进程**愿意加载 `addons\` 下的未签名 DLL。听服就开在你（房主）的游戏进程里，
metamod / SourceMod / kgns / bot 插件全在你机器上；朋友的客户端只是连进来，
一行插件代码都不执行。皮肤也是同一回事——插件把 paintkit / wear / seed **写在武器实体上**，
经普通网络同步传到每个客户端，渲染用的是客户端自己就有的官方素材，所以朋友那边不需要任何注入或补丁。
（`sv_pure` 在这个 build 的 13881 里根本不存在，也不会有"纯模式拒绝自定义内容"这回事——
本来就没有自定义内容。）

他唯一会感受到的差别是：聊天里 `!ws` / `!knife` / `!gloves` 这些命令由**你的服务器**响应。
还没验的一项是**他的皮肤能不能存住**：`-insecure` 的听服不做玩家认证（日志明写
`Authentication and VAC not requested`），而 kgns 的皮肤表以 SteamID 为主键，
所以"连进来之后他的 SteamID 还在不在"必须等第二台机器才能测（见
[开局与自动启动](开局与自动启动.md) 末尾那一节）。

## 连不上时按这个顺序查

1. **他和你是不是一个网段。** `join` 会打印类似 `同网段范围 192.168.16.1 - 192.168.31.254
   (192.168.16.0/20)`。朋友的 IP 不在这个区间里就不是防火墙问题，是路由 / 不同 AP 的问题。
2. **服务器在不在。** 别看端口——CS:GO 客户端自己就会绑 UDP 27015，停在主菜单时也一样，
   `join` 打印的占用信息不能证明有服务器。真正的判据是文件管道有没有被插件吃掉：
   `csgotool.py status` 几秒内回数据就是在对局中，超时就是还没开局（或 ESC 暂停中）。
3. **防火墙。** 工具会打印需要管理员权限执行的
   `netsh advfirewall firewall add rule ... localport=27015`，你自己复制到管理员终端跑。
4. **别去翻服务器列表。** 这个 build 完全不应答 A2S（真跑图的服务器上 `A2S_INFO` / `A2S_PLAYER` /
   `A2S_SPLIT` 全部超时），局域网列表里永远看不到这个房间，只能 `connect`。这不是故障。

## 密码房

```
python tools\csgotool.py lan --password hunter2
```

改 `lan.cfg` 里的 `sv_password`（旧文件自动备份成 `lan.cfg.bak`）并立即 `exec`。
之后 `join` 打印的三种写法都会自动带上密码。

## 两个版本

| | 房主端 | 朋友端 |
|---|---|---|
| 文件 | `exe\csgo-server-tool.exe` | `exe\csgo-room-client.exe`（8.2 MB） |
| 谁用 | 只有你（跑游戏这台机器） | 每个朋友自己拷一份 |
| 能做什么 | 全部：开服换图、规则、bot、皮肤、诊断 | 记地址、试连通、**一键进房**、看自己能敲的命令 |
| 权限 | 全权限 | **结构上没有任何写权限** |

朋友端的"不能改 bot / 不能改房间参数 / 不能碰 cfg / 不能开图"不是靠权限检查实现的——
那个程序里**根本没有这些代码**：不 import 管道模块、不含 lan_fix 命令、不碰 SQLite 和 cfg，
只用了 `socket` + `os.startfile`。就算对方把 exe 反编译也拿不到能力。
它唯一会写的文件是自己旁边的 `room.ini`。

## 分发包

房主端菜单 **7 联机与加入 → 8 生成分发包**，或命令行：

```
python tools\csgotool.py kit
```

生成 `dist\房间包-<你的IP>\`，里面三样：

```
进房.exe      客户端（地址已经写进去了，对方不用输）
room.ini      host / port / password / name
说明.txt      双击→按 1 进房；!ws 选皮肤；连不上怎么查
```

**整个文件夹发给对方就行。** 你的局域网 IP 变了要重新生成一次（`kit` 会把当前地址打印出来）。

## 别把 sv_lan 设成 1

那会让所有人拿不到 SteamID，而 kgns 的皮肤表是按 SteamID 存的、`GetClientAuthId` 又是失败即返回
且没有 else 分支——结果是所有人的皮肤、手套、刀全部丢失且不会保存。`set sv_lan 1` 会被工具拒绝，
除非你加 `--force`。
