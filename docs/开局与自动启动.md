# 开局与自动启动

← 回到 [README](../README.md)

这一节全是实测出来的边界。它解释一个问题的两面：**为什么工具能一条命令把对局开起来，
但那个对局不是你想要的竞技局。**

## 能做到的：一条命令把带插件的对局开起来

```
python tools\csgotool.py start de_nuke --launch
```

直连 `csgo.exe`，命令行是 `-insecure +game_type 1 +game_mode 0 +map de_nuke`。实测日志顺序
`VAC secure mode disabled` → `---- Host_NewGame ----` → `Host_NewGame on map de_nuke` →
UI `MAINMENU → LOADINGSCREEN → INGAME`，8 个 mod DLL 全在进程里，`status` 直接回数据。

两个必需条件：

1. **`-insecure`**。没有它引擎根本不把 addons 里的 DLL 装进进程（VAC 安全会话拒绝未签名模块），
   起来的是个没有插件的空壳对局。
2. **安装目录的 `steam_appid.txt` 必须是 4465480**。出厂值 730 是 CS2，Steam 因此拒绝给直连进程
   会话，进程只卡在 Launcher Error 弹窗上（约 16 MB，不动）。工具在每次直连前把它对齐，
   原值备份在 `backup/steam_appid.txt.orig`。曾经把失败归因于"直接跑 exe 一定不行"，
   **那个结论是错的**，拦路石就是这个文件。

走过的弯路记在这里免得重犯：`steam://run/4465480//+map …` 的参数是 **Steam 客户端丢的**
（不是引擎不认）；`-condebug` 是最干净的探针——启动选项里带上它，`csgo/console.log` 出现
就等于参数进了引擎。测完记得清掉，`console.log` 被游戏独占，运行中删不掉。

## 做不到的：让它开成竞技局

**最终结论（2026-10-31 18:0x 实测）**：无论工具直连还是 Steam 启动选项，`+map` 开出来的对局都是
**非竞赛玩法**（日志 `exec: couldn't exec gamemode_armsrace_server.cfg`，`cash_*` 奖励 cvar 全为 0），
而且**已创建的对局无法用 cvar 改玩法**——写 `game_type`/`game_mode` 再 `changelevel` 都不换规则
（`game_type` 读回来一直是 1/0，是骗人的）。

原因：玩法在 Panorama 主菜单创建 session 那一刻就定了（`matchmaking.dll` 里的 `offlineinit` 会话命令），
控制台里根本没有创建离线对局的命令（`session_send` / `start_offline` / `create_offline`
在 engine/client/server/matchmaking 四个 DLL 里都搜不到）。

所以：

- **判据是 `csgotool.py mode`**——按 `gamemode_*.cfg` 的 cvar 指纹识别，且故意不含我们自己 cfg
  碰过的键，宁可报"平局"也不猜。
- **要竞技局就点一次 开始游戏 → 与电脑玩家**，之后 `start <图>`、换图、规则、bot、皮肤全自动。
- **主菜单状态下 SourceMod 不加载**（它是 server 侧框架，菜单图没有服务器），所以没开局时
  工具连不上是正常现象，不是插件坏了。

直连启动还有两个实测代价，所以正经玩不要用它的（Steam 启动选项那条路没有这两个问题）：

- **拿不到 Steam 用户会话**：日志里 `AuthStatus ... Failed (No response from server)` 和
  `Authentication and VAC not requested`，表现为键位、灵敏度、视频设置**像**被清空。磁盘上的
  `Steam\userdata\<你的 SteamID64>\4465480\local\cfg\config.cfg` 一字节没动、mtime 没变，
  下次正常启动就回来了。
- `+game_type` / `+game_mode` 落得太晚，`Host_NewGame` 已经按引擎默认模式建好了。

## 为什么没有"真·后台开服"

完美 / 5E 那类平台点一下就进房，靠的是三件查过的东西：他们**自己拥有服务器**，把
`+connect ip:port 密码` 交给**游戏自己的命令行**，而引擎会把 `+connect` 延后到主菜单就绪再执行
（`csgo/bin/client.dll` 里就有 `Executing deferred connect command: %s.`）。顺带一提，这份
`client.dll` 里还留着 `#SFUI_LoginPerfectWorld_Offline20221206` 这个本地化 token——
完美世界登录本来就集成在这个客户端里，所以那是正规通道，**不是进程注入**。

要真正做到"不开游戏窗口也有房"，需要专用服务器（srcds），而这台 install 给不出来：

- `appmanifest_4465480.acf` 与 Steam 的 appinfo 缓存里，这个 app 的可执行文件只有 `csgo.exe`
  （启动参数 `-steam -worldwide`），`oslist` 只有 `windows,macos`，安装目录根下也确实没有 `srcds.exe`。
- 当年的 CS:GO 专用服工具 appid 740 已不在本机 appinfo 缓存里；acf 里 depot 735/736 有 manifest
  但 `size 0`（没下载）。它们是不是 dedicated 内容，要用 SteamCMD 的
  `app_info_print 4465480`（只读）才能确认。
- 引擎侧并不排斥：`engine.dll` 有 dedicated 代码路径，`matchmaking.dll` 里有一整组
  `mm_dedicated_allow / mm_dedicated_fake / mm_dedicated_force_servers / mm_dedicated_ip`。
  所以这是"能不能装到"的问题，不是架构上不可能。
- 就算装上了还有第二道坎：专用服要保持 `sv_lan 0` 才拿得到玩家 SteamID（皮肤就是按 SteamID 存的），
  而 srcds 认证需要 `sv_setsteamaccount` 的 GOTL token；legacy 分支还能不能申请到 token 未知。
  拿不到就只能退回 `sv_lan 1`，那又会丢掉所有人的皮肤保存。

所以现在这台机器的形态是：**一个必须开着游戏窗口的 listen 服**。窗口不需要人盯，但必须在对局中。

## 朋友能不能连进来：本机测不出来

- `steam://connect/ip:port` **不是没反应**：链接确实送到了游戏，但握手被 Steam 拒绝，客户端弹
  「无法连接服务器——服务器指定的 app id 无效」。之前那条"管道连续应答 = URI 没生效"的推理是错的：
  应答不断只是因为握手早就失败、对局从没重载。
- 原因候选定位到了：`csgo/gameinfo.txt` 的 `FileSystem → SteamAppId` 写的是 **730**，而本机
  安装/启动的是 **4465480**。改成 4465480 试过一次（原文件备份 `backup/gameinfo.txt.orig`，
  SHA-256 `af6a607e…dbaa`，一键还原 `backup/restore-gameinfo.cmd`）：游戏照旧正常启动到主菜单，
  说明这个值不参与内容挂载、改动本身安全；但因为下面那条，**这个改动到底解不解锁在本机测不出来**，
  所以已还原回 730。
- 同机第二实例这条路仍然封闭：房主本来就不能加入自己开的 listen 服，跟注入通道无关。
- 结论：要答案只能等第二台机器 / 第二个账号。届时先看他在控制台
  `connect <房主局域网 IP>:27015` 是否还报 app id 无效——那才是判定 gameinfo 这一改有没有生效的证据。
- `-insecure` 下这台 listen 服不做玩家认证（日志明写 `Authentication and VAC not requested`），
  所以"连上后他的 SteamID 还在不在（决定他的皮肤能不能存）"也是同一批待验项目。

## 只有屏幕上能看到的错误，也能被工具读走

```
python tools\csgotool.py dialog [--pid N]
```

枚举 csgo.exe 的窗口，把弹窗原文打出来：窗口类 `#32770` = 错误弹窗，`Valve001` + Direct3D 标题
= 游戏真的起来了。启动失败时不用再抄给我看。
