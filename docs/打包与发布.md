## 重新打包两端 exe

改了 `.py` 之后要重出 exe。一条命令，PyInstaller 只是这个脚本的依赖、运行时不需要它：

```
python tools\build_exe.py                # 两端都出，出完自己跑一遍冒烟检查
python tools\build_exe.py --only server  # 只出房主端
```

脚本干三件事：

1. 确认环境里有 PyInstaller（没有就打印 `pip` 命令，**不替你装**）。
2. 用固定的 `--onefile --console --add-data` 参数打包到 `exe\`。参数都收在
   `tools\build_exe.py` 的 `TARGETS` 里，别在文档里手抄命令行。
3. **拿产出的 exe 真的跑几条命令**：`--help`、`install --list`、
   `install --audit --into <一个不存在的路径>`；朋友端没有参数，喂空 stdin 让菜单画一遍就退出。
   每项打印 `[ok]` / `[!!]`，任何一项没过退出码 1。

最后附每个文件的字节数与 SHA-256。**那串哈希就是该写进 Release 说明的东西**——下载方能据此
判断 exe 有没有在这次构建之后被动过。未签名 exe 会吃 Windows SmartScreen 提示，
不买代码签名证书解决不了，发出去时在说明里提一句。

两个坑已经踩过并处理了：

- **不能用 `--noconsole`**：这类程序要读键盘，去掉控制台后双击既没窗口也读不到输入。
- `__file__` 在 onefile 下指向临时解压目录，所以所有输出目录锚在 `sys.executable` 旁边
  （否则 `join --write-cmd` 生成的文件会随临时目录一起消失）。
- 另外：`shell_ui` 是在函数里 import 的，必须用 `--hidden-import` 显式告诉打包器。

## 发布前跑这四条，别靠眼睛看

```
python tools\secret_scan.py --all-objects   # 扫工作区 + 全部 git 对象 + 提交身份
python tools\csgotool.py install --check     # 核对现场与 components.json（0 = 一致）
python tools\csgotool.py install --audit     # 静态自检：坏东西退 1，建议不影响退出码
python tools\build_exe.py                    # 两端 exe 能跑，顺带打印要写进 Release 的 SHA-256
```

- `secret_scan.py` 要查的"我自己的标识"（SteamID64、局域网 IP、主机名、提交邮箱）放在
  **被 gitignore 排除**的 `.secrets.json` 里——把待查的值写进扫描器源码，等于用它要保护的东西
  污染仓库，所以仓库里只有 `secrets.example.json` 模板。换机器时先复制模板填自己的值。
  代码里只允许留**按形状**匹配的正则（SteamID 三种形式、RFC1918、MAC、AKIA/ghp_/私钥/bearer/cookie、
  `users\|userdata\|home` + 用户名这种路径形状）。
- **每个新提交都要重跑** `--all-objects`：这台风机的 git 全局身份是作者的真实邮箱，
  一个普通 `git commit` 就会把它写进历史。提交时要显式带上
  `git -c user.name=... -c user.email=... commit`（不改 git 配置），修历史要
  `--amend --reset-author`（只 `--amend` 只改 committer，作者还留着），之后
  `reflog expire --expire=now --all` + `gc --prune=now`，否则旧对象里那份还可达。
- `--check` 认得 `bots patch` 的产物（哈希在 `backup\bots\*\report.json` 里出现过就算正常），
  所以拉平过强度的机器上这条门仍然是绿的——门不该逼你把自定义改回去。
- 行尾由 `.gitattributes` 钉死（批处理 CRLF、`.py/.sp/.cfg/.md` LF、`backup/**` 与 `*.orig`
  标 `-text` 禁止任何改写），因为备份文件的作用是按字节还原。

## 许可与再分发

**本仓库自己产出的东西**（`tools/*.py`、`tools/src/*.sp`、`release/plugins/*.smx`、`configs/*.cfg`、
`configs/components.json`、文档）按 **GPL-3.0-or-later** 授权，全文见 [LICENSE](../LICENSE)。
选它的理由不是跟风：`lan_fix.sp` / `lan_pipe.sp` 是通过 SourceMod 的 include 链编译的，而
SourceMod、Metamod、PTaH、kgns weapons/gloves、sm-ripext、eItems 全是 GPL-3.0，
插件产物与它们构成同一套作品，用同一个 copyleft 最省事也最不容易出错。

**第三方组件一律保留自己的许可**，本仓库不重新授权它们，也不打包它们——每一项的来源、版本、
许可和被排除的原因都写在 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。两个要点：

- `manicogaming/CSGOBetterBots`（bot 强化那批）**没有 LICENSE 文件**，所以只允许你自己在
  `install` 显式确认后按固定 commit 从上游抓——`botprofile.db` 就是这么抓下来的上游文件，
  仓库里不放它。
- Valve 自己那份原始 `botprofile.db`、`gameinfo.txt` 属于我们无权分发的事物，只留本机的
  `backup\` 里用于还原。`bots patch` 同理：它改写**你自己机器上**的 db，不带任何人的文件。

## 已知的下一个缺口

首装要现拉约 76 MB（sourcemod 64 + mmsource 5 + botpack 4.4），没有断点续传也没有镜像，
`--no-fetch` 在缓存为空时直接报错而不是接受一个本地目录。补法是 `install --from <目录>`
加把归档挂成 Release 资产。
